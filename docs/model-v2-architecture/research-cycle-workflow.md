# Research Cycle Workflow — Phases 26-27

## Overview

Two full research cycles (Cycle 1 = Phase 26, Cycle 2 = Phase 27), each with 4 focus areas.
Each focus area has 3 steps of 2 agents in parallel.

## Structure Per Focus Area

1. **Step 1:** 2 research-readers (online research, DIFFERENT search paths)
2. **Document findings** → split into parts if >400 lines
3. **Step 2:** 2 math-paradigm-breakers (mathematical analysis of findings + novel formulations)
4. **Document findings**
5. **Step 3:** 2 paradigm-breakers (radical alternatives, completely different approaches)
6. **Document findings**

## Focus Areas (same for both cycles)

- **A: Computational Efficiency** — Training speed, algorithmic improvements
- **B: Memory Optimization** — Weight compression, activation memory, optimizer state
- **C: Quality/Intelligence** — Architecture improvements, training techniques, closing ternary gap
- **D: Inference** — Inference speed, serving efficiency, deployment

## Critical Rules

1. At START of each focus area: compile ALL existing findings into context for agents
2. Agents must receive: what we ALREADY HAVE, what ALREADY FAILED, what the GOAL is
3. Emphasize: we want PARADIGM SHIFTS, not incremental improvements
4. The goal: super intelligent, lightest possible, fastest to train/infer
5. Maybe something COMPLETELY DIFFERENT from current architecture
6. Keep finding files under 400 lines — split into parts
7. Number findings sequentially from last number (currently Finding 106)
8. Cycle 2 agents receive ALL Cycle 1 findings

## The Ultimate Goal

Not just "improve ternary SSM by 5%". We want:
- Something that can THINK and respond correctly
- Drastically lighter than anything existing
- Drastically faster to train (or equivalent process)
- Open to COMPLETE paradigm changes if needed
- If the answer is "don't use neural networks", that's valid
- If the answer is "don't use backprop", that's valid
- If the answer is "don't use weights at all", that's valid
